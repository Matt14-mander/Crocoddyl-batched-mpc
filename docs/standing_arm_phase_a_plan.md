# 站立带臂规划对照实验实施计划

制定日期为 2026-11-13。本文定义阶段 A 的实现范围、仓库分工、模型接口和验证顺序。新增控制模块与实验步骤按方案推进；已完成的库级基线和资产准备在相应段落单独记录。

## 研究目标

在四足固定支撑条件下，让带臂机器人跟踪世界坐标系手端轨迹，比较质心规划与全身规划为同一个 WBC 提供的参考可执行性。重点观察机械臂伸展、运动速度和载荷增加后，全身动态预测是否改善真实物理闭环表现。

阶段 A 使用脚本任务参考。后续 RL 沿既有 RL-guided MPC 路线学习调整身体运动参考，部署时继续执行 MPC。是否推进 RL，由阶段 A 的对照结果决定。

## 共同任务与控制链

四个足端世界锚点固定，基座允许在约束范围内平移和倾斜。手端固定朝向，跟踪速度与加速度连续的侧向往返轨迹，再加入少量前伸。

执行链为实测状态与任务预览进入 C0/C1/W 规划器，输出 Guidance，再由同一个 WBC 生成全部关节力矩，最终由 PhysX 推进真实状态。

所有方法共享初始条件、目标预览、物体参数、接触计划、WBC 和执行器设置。优化器的预测轨迹只用于计划与诊断，实际轨迹由物理引擎状态记录。

## C0 质心规划

状态取 `x_c = [c, l, k]`，分别表示总质心、线动量和质心角动量。控制为四足接触力 `u_c = [f1, f2, f3, f4]`。

连续动力学为

- `dc/dt = l/m`
- `dl/dt = m*g + sum(f_i)`
- `dk/dt = sum((p_i-c) cross f_i)`

固定足端位置为 p_i。刚性末端载荷计入总系统质量和质心，避免重复加入手端外力。

约束包括法向力范围、摩擦棱锥、质心高度与移动区域、接触力变化率。双线性力矩项采用顺序线性化 QP，配合信赖域与完整动力学残差检查。

共同运动学参考生成器在未来手端目标、足端锚点和关节范围下求解全身姿态序列，平衡手端误差、姿态偏移与时间平滑性。由该序列生成质心和基座姿态参考，C0 跟踪这些参考并调节动量与接触力。

## C1 增强质心规划

在 C0 上增加构型相关质心/动量映射，以及准静态全身平衡检查。检查各节点姿态下的支撑力、关节力矩和载荷承载能力。

若参考超出能力范围，在允许范围内重新分配基座和机械臂姿态；仍不可行时返回明确状态。记录运动学和准静态处理时间。C1 用于判断 W 的增益是否可以通过较便宜的构型感知近似获得。

## W 全身规划

状态为浮基与关节状态 `(q,v)`，控制为全部 18 个驱动关节力矩。四足固定接触满足

- `M(q)*dv/dt + h(q,v) = S^T*tau + J_f(q)^T*f`
- `J_f(q)*dv/dt + dJ_f/dt*v = 0`

每个节点有独立控制，采用流形积分。目标包含手端位置与姿态、基座与质心运动、名义关节姿态、速度、力矩及控制变化。控制变化代价需要通过状态增广或支持相邻控制耦合的 formulation 明确实现。

首版采用原生 Crocoddyl Box-FDDP 建立 CPU 参考问题。力矩 box 使用求解器机制；摩擦和状态范围若采用 barrier，应明确为软约束，并对最终轨迹逐节点检查。记录动力学 gap、关节范围、摩擦、法向力和力矩违反量。失败轨迹进入统一回退并计入统计。

C0/C1 与 W 的首版求解方法不同。先给足预算检查模型质量，再做固定计算预算对照，分别报告数值收敛和模型效果。Torch/JAX 迁移由瓶颈测量与阶段 A 结果决定。

## Guidance 与统一 WBC

`MPCResult` 保存各求解器原生状态和控制；`Guidance` 提供跨模型共同接口。

共同字段包括时间戳、有效期、有效状态、质心位置/速度/加速度、基座姿态/角速度、手端位姿/速度/加速度、名义关节参考、接触力参考和诊断。统一坐标系、单位、节点时间与插值规则。

首轮三组使用共同运动学生成器提供的名义关节参考。W 自身的关节轨迹用于诊断；将其送入 WBC 作为独立消融，分离模型质量与额外监督信息的影响。

WBC 决策为 `[dv/dt, f, tau]`。硬约束包含全身动力学、四足接触加速度、力矩范围、摩擦与法向力范围。关节位置/速度范围通过下一步预测构造约束。任务目标包含手端、质心、基座姿态、名义关节姿态、力参考与控制变化，使用相同权重和增益。

新规划失效时短暂沿用有效旧参考，超期后平滑过渡到稳定站立参考。WBC 无可行解时终止回合并记录原因。突然全零力矩不作为站立带臂任务的默认恢复策略。

## 与现有 non-gait 工作的接口隔离

带臂任务新增环境、adapter、模型配置与控制模式。当前 Go2 动作含义、接触状态机和旧 checkpoint 接口保持兼容。

现有 `Go2TrackingMPC` 直接输出腿力矩。阶段 A 的规划参考加统一 WBC 是独立执行路径，避免叠加两套力矩控制或重复 PD。

集成仓库旧 NumPy 协议 `interfaces/protocol.py` 固定 q=19、v=18。带臂路径使用独立的模型规格和 Tensor 接口；若将来合并协议，应覆盖旧任务回归。

non-gait 与带臂任务共享的求解器、流形和 reset 改动集中评审。当前 non-gait 的奖励及动作采纳诊断使用独立配置。新增带臂模型与固定支撑 WBC 可并行开发。

## 指标与实验判据

记录手端 RMSE/峰值误差、基座位移/倾角、足端滑移/抬足、失败率、力矩饱和时间、WBC 任务残差、规划与执行偏差、回退比例、求解时延和超时率。

WBC 为实现参考作出的调整使用共同任务空间残差衡量，避免比较不同规划器的原生控制向量。全部失败回合进入统计，各规划器内部代价只作诊断。

若 W 在困难工况中稳定改善真实执行，相比 C1 仍有收益，且计算成本可接受，则进入 RL 参考生成实验。若 C1 与 W 接近，优先研究较便宜的指导。若固定支撑差异很小，可据结果决定是否加入接触切换。

阶段 A 支持固定支撑操作结论。行走中的 loco-manipulation 能力需要后续移动任务验证。

## 实施顺序与交付

1. 固定两仓库提交，运行 adapter 导入及现有 Go2 站立回归，确认实际依赖版本。
2. 选择机械臂资产，核对 FK、质心、质量、重力补偿和全关节力矩映射。

4. 接入 C0/C1/W，完成 12 个空载配对场景与求解质量检查。
5. 完成 36 个带载配对场景，输出配置、版本、原始日志、视频和指标表。
6. 根据结果决定 RL 参考动作和奖励设计，再复用现有训练生命周期。
