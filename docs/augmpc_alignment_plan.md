# Go2 AugMPC 核心方法对齐实施计划

制定日期为 2026-11-11。本文记录已确认的实施方向，阶段状态以实验产物更新。

## 目标与完成定义

在 Go2 平地仿真中，高层状态反馈策略持续输出导航参考和四足独立摆动请求，底层 MPC 根据滚动接触序列执行运动。通过同条件对照，证明学习得到的接触时序能够适应任务变化，并改善固定步态或规则控制的表现。

同时推进本仓库原始目标，将已有 Torch DDP/FDDP 在明确的问题范围内与 Crocoddyl CPU 参考求解器对齐，并接入 Isaac Lab 实际训练链路。

核心验收覆盖持续导航、逐足接触调度、批量求解、学习收益及消融。实机、多机器人形态、轮腿运动和复杂地形列为后续扩展。论文的全部实验设置与本项目的核心方法验收分别记录。

参考论文为 *RL-Augmented MPC for Non-Gaited Legged and Hybrid Locomotion*。论文使用 SAC、接触显式的分层控制和多节点 MPC。PPO 可用于本项目早期接口验证；是否引入 SAC，由样本效率实验决定，并在最终方法描述中保留算法差异。[论文](https://arxiv.org/abs/2603.10878) · [官方实现](https://github.com/AndrePatri/AugMPC)

| 3B | Torch DDP/FDDP Go2 数值对齐报告 | 复用已有求解器，待扩展 |

以下数值为项目建议验收标准。各阶段实验开始前将指标定义和门槛固定到配置，报告失败案例。调整门槛时保留理由及原始结果。

## 阶段 0 — 冻结当前 Stage 2 基线

**代码工作**

- 复用集成仓库 `train_stage2_async8.py` 和 `stage2_training_state.py` 的续训、checkpoint 与阶段复评功能。
- 增加第 0 轮初始化策略的确定性复评，整理第 1、4、8、12 轮结果。
- 记录两仓库 commit、软件版本、配置、种子、策略、优化器和采样状态。

**实验**

- 规则控制器、初始化策略、各轮策略使用相同初始条件和目标。
- 先复现 3/6 mm/s 任务，再测试未训练的中间速度。
- 记录成功率、速度误差、到达时间、终点误差、档位分布与失败原因。

**验收**

- checkpoint 重载后的确定性动作一致，续训状态与计数可核对。
- 所有控制器完成同条件评估，失败回合进入总体统计。
- 明确训练相对初始化的变化，并区分人工初始化带来的行为。
- 未观察到学习收益时，结论记录为“接口通过、收益未验证”，继续推进后续环境和求解器工作。

## 阶段 1 — 持续反馈环境与状态观测

**代码工作**

- 在集成仓库 `source/RL_Bezier_MPC/RL_Bezier_MPC/envs/` 新增 `go2_augmpc_env.py` 及对应配置。
- 从 `check_stage2_async_reset.py` 提取逐环境时钟、episode 身份和 reset 管理，复用基础环境的机器人、传感器及扭矩写入。
- 建立固定频率高层入口，初始采用 4 Hz 策略和 50 Hz 控制；记录实际时间步与决策时刻。
- 统一观测布局，纳入目标参考、重力方向、角速度、关节状态、动作历史、MPC 健康和接触计划摘要。分别记录实测速度与 MPC 估计速度及其来源。
- 使用明确的 terminated/truncated 语义，核对 bootstrap、奖励累计和动作保持时长。

**实验与验收**

- 八环境持续运行至少 60 s 仿真时间，覆盖目标变化、不同长度回合和局部 reset。
- 动作、奖励、接触计划和 warm start 无跨环境串扰；旧回合请求在 reset 后失效。
- 所有观测、动作与奖励有限，执行频率匹配配置。
- 为采样身份、reset 和终止语义添加针对性回归测试。

## 阶段 2 — 四足独立接触调度

**代码工作**

- 在 MPC 仓库新增 `src/crocoddyl_batched_mpc/models/go2_contact_schedule.py`，维护逐环境、逐足、逐节点接触序列。
- 复用适用的切换和冲击逻辑，定义支撑、待摆动、摆动、触地、承重恢复状态。
- 定义请求注入节点、重复请求、同足摆动重叠、同时请求及提前/延迟触地的行为。
- 初期固定摆动时长和抬脚高度；提取现有摆足参考和恢复逻辑为公共实现。
- 记录原始请求、接受/延迟/拒绝原因与实际执行事件。

**实验与验收**

- 执行单足、对角双足、不对称顺序和不等间隔请求，覆盖重复请求及运动中 reset。
- 至少三类非周期序列连续执行 30 s，无跌倒或未处理的求解失败。
- 支撑锚点仅在相应足确认触地时更新；接触请求与状态转换可逐事件追溯。
- 报告调度干预率，明确哪些动作来自策略请求、哪些受到可行性规则影响。
- 此阶段可先验证调度数据和受控序列；依赖多节点求解的闭环能力在阶段 3C 完成验收。

## 阶段 3A — Go2 Crocoddyl CPU 参考问题

**代码工作**

- 复用 Go2 模型、现有 Crocoddyl 对照测试和流形工具，建立固定支撑到指定接触切换的参考问题集。
- 固定 Crocoddyl/Pinocchio 版本、URDF、状态与切空间顺序、坐标系、积分、代价、约束处理和初始轨迹。
- 显式选择 SolverDDP、SolverFDDP 或 Box-FDDP 对应的比较范围。控制界通过相应求解机制处理，记录裁剪与约束优化各自发生的位置。
- 对切换节点的接触模型、冲击映射和代价导数逐项配对。

**实验与验收**

- 覆盖固定支撑、单足摆动、对角双足和不可行初始轨迹。
- 导出每例初始轨迹、优化轨迹、首步力矩、代价、动力学 gap、约束残差与迭代记录。
- 导数通过独立有限差分或已有解析参考核对，检查 frame 与 nx/ndx 语义。
- 所有案例可固定配置复现，明确哪些约束为硬约束、代价惩罚或执行检查。

## 阶段 3B — 完善已有 Torch DDP/FDDP 并数值对齐

**代码工作**

- 在已有 `backends/torch_ddp.py`、`ddp_problem.py` 和相关工具中实现必要扩展。
- 对照 Crocoddyl 的 expected-improvement、步长接受、正则化、停止及可行性恢复行为。当前 L1 merit 与参考行为的差异需要明确记录。
- 支持逐节点控制和未来接触序列，接触掩码契约采用 `[B,T,4]` 或与节点定义一致的等价表示。
- 新增 `models/go2_contact_mpc.py` 组织 Go2 多节点问题；预测时域覆盖完整摆动及部分落足后支撑阶段。
- 定义 horizon shift、跨接触 warm start、模型更新和局部 reset 的缓存失效规则。

**实验与验收**

- 依次比较模型值/导数、单次 backward/forward、步长接受、多次迭代和最终解。
- 覆盖可行/不可行初值、非正定局部问题、预算耗尽、接触切换与异常环境隔离。
- 从单环境 CPU 扩展到批量 CPU/CUDA，容差按问题尺度和精度在实验前固定。
- 不同局部解需要解释可行性、代价与控制差异；严格迭代对齐与最终性能接近分别报告。
- 初始状态相同、未来接触不同的受控案例中，当前优化结果应体现未来计划的影响。
- 已有 DDP/FDDP 和模型回归通过；只有实际执行通过的设备路径计入验收。

## 阶段 3C — Isaac Lab 新后端闭环

**代码工作**

- 为新环境加入显式后端选择，接入多节点 Torch 求解器及 Crocoddyl CPU 参考。
- 复用 `go2_tensor_adapter.py`，统一坐标转换和扭矩映射。
- 按失败类型定义可用解、回退及 episode 终止行为，记录失败连续长度。
- 区分物理步长、控制周期和墙钟求解时间；需要实时部署时另行验证延迟补偿。

**实验与验收**

- 在相同初态及接触计划下比较 CPU 参考、Torch 后端和原局部 QP。
- 单足、对角双足、不对称序列各至少 20 次，成功率达到 95%。
- 记录跟踪误差、接触力、约束残差、回退率及求解耗时 P50/P95/P99。
- 核对独立环境与批量结果、局部 reset 以及长时间状态一致性。
- 仿真配置频率与实际实时性能分别报告。

## 阶段 4 — 导航与接触策略学习

**代码工作**

- 集成仓库新增 `scripts/train_go2_augmpc.py`，策略及 rollout 逻辑放入可复用包模块。
- 动作组织为六维机身速度参考和四足独立摆动请求；初期限制垂向及 roll/pitch 参考范围。
- 使用阶段 1 的状态观测和阶段 2 的接触摘要，验证终止、bootstrap 与奖励时间尺度。
- 保存采样动作及原始概率，另存调度器实际执行结果，确保被拒绝或限制的动作仍有正确训练归属。
- 初始奖励包括速度跟踪、失稳终止及适度动作变化惩罚；能耗、滑移和 MPC 健康先作为诊断量记录。

**实验与验收**

- 课程依次覆盖站立、低速前进、加减速、停止及方向变化。
- 至少 3 个训练种子，每种子至少 20 个独立评估回合；冻结评估配置并关闭探索。
- 初步成功率达到 90%，同时报告回退率和请求干预率，审查持续回退带来的表面成功。
- 展示随目标变化的接触时序调整，对比初始化与固定调度。
- 若采样成本成为主瓶颈，在相同接口及交互预算下比较 SAC 与 PPO，记录总交互量和墙钟耗时。

## 阶段 5 — 持续导航与任务收益

**代码工作**

- 增加平面目标到速度参考的映射、目标切换和持续导航配置。
- 新增 `scripts/evaluate_go2_augmpc.py`，统一控制器输入、指标和失败统计。
- 导出逐时刻接触序列、速度、策略动作和 MPC 状态。

**实验**

- 按当前能力逐级验证 0.02、0.05、0.1 m/s，再依据控制余量扩展。
- 对比固定 crawl、固定 trot/调参规则、学习导航加固定调度、学习导航加学习调度。
- 统一目标、初态、可用传感器和底层控制条件，覆盖未训练速度、停止、转向和侧向运动。

**验收**

- 连续至少 60 s，包含多次速度或方向变化，导航成功率达到 95%。
- 预先固定主要指标，例如目标变化时的速度跟踪误差；相对最佳基线改善至少 10%，成功率下降不超过 2 个百分点。
- 至少 3 个种子，报告均值、离散程度和置信区间。10% 为预注册目标，未达到时保留完整结果并分析原因。
- 到位与停稳阈值按导航尺度重新固定，保留此前厘米级任务作为回归案例。

## 阶段 6 — 消融、稳健性与复现

**实验**

- 固定/学习接触调度、移除接触摘要或 MPC 健康观测、不同策略频率和预测长度。
- 平面推扰、质量、摩擦及控制延迟变化，记录具体扰动范围。
- 测量 8/16/32 环境的有效采样吞吐、求解失败及显存，在硬件允许时扩展。

**验收与产物**

- 使用冻结 checkpoint；测试集与训练目标分离，策略评估关闭探索。
- 发布配置、代码版本、训练曲线、逐回合结果、接触图和成功/失败视频。
- 结果能够回答接触时序何时改变、为何带来收益，以及跨目标和种子是否稳定。
- 形成核心对齐报告，列明与论文在求解器、算法、观测和实验范围上的差异。

## 执行与状态更新约定

- 每阶段记录代码 commit、实验命令、配置、设备、种子、结果路径、失败数及结论。
- 聚合 JSON 与可复现实验配置随实验提交；大型 checkpoint、视频与原始轨迹提供稳定产物位置。
- 单次更新、参数变化、物理验收通过和学习收益成立分别记录。
- 阶段 3 为主要技术风险，先完成单环境最小接触问题及数值对照，再扩大训练。
- 完成阶段 4 可报告 Go2 接触显式 RL-MPC 原型；阶段 5 与关键消融通过后，报告 Go2 上 AugMPC 核心方法对齐。
