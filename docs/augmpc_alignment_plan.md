# Go2 AugMPC 核心方法对齐实施计划

制定日期为 2026-11-11。本文记录已确认的实施方向，阶段状态以实验产物更新。

## 目标与完成定义

在 Go2 平地仿真中，高层状态反馈策略持续输出导航参考和四足独立摆动请求，底层 MPC 根据滚动接触序列执行运动。通过同条件对照，证明学习得到的接触时序能够适应任务变化，并改善固定步态或规则控制的表现。

同时推进本仓库原始目标，将已有 Torch DDP/FDDP 在明确的问题范围内与 Crocoddyl CPU 参考求解器对齐，并接入 Isaac Lab 实际训练链路。

核心验收覆盖持续导航、逐足接触调度、批量求解、学习收益及消融。实机、多机器人形态、轮腿运动和复杂地形列为后续扩展。论文的全部实验设置与本项目的核心方法验收分别记录。

参考论文为 *RL-Augmented MPC for Non-Gaited Legged and Hybrid Locomotion*。论文使用 SAC、接触显式的分层控制和多节点 MPC。PPO 可用于本项目早期接口验证；是否引入 SAC，由样本效率实验决定，并在最终方法描述中保留算法差异。[论文](https://arxiv.org/abs/2603.10878) · [官方实现](https://github.com/AndrePatri/AugMPC)

## 阶段 1 — 持续反馈环境与状态观测

**代码工作**

- 在集成仓库 `source/RL_Bezier_MPC/RL_Bezier_MPC/envs/` 新增 `go2_augmpc_env.py` 及对应配置。
- 从 `check_stage2_async_reset.py` 提取逐环境时钟、episode 身份和 reset 管理，复用基础环境的机器人、传感器及扭矩写入。
- 建立固定频率高层入口，初始采用 4 Hz 策略和 50 Hz 控制；记录实际时间步与决策时刻。
- 统一观测布局，纳入目标参考、重力方向、角速度、关节状态、动作历史、MPC 健康和接触计划摘要。分别记录实测速度与 MPC 估计速度及其来源。

**实验与验收**

**代码工作**

- 复用适用的切换和冲击逻辑，定义支撑、待摆动、摆动、触地、承重恢复状态。

**实验与验收**

**实验与验收**

## CMA-ES、手工规则与 PPO 的公平对照协议

本节为待实施实验设计。阶段 0 先使用现有周期级接口，阶段 4–5 再扩展至逐足动作。每组实验固定同一个底层后端；局部 QP 与 DDP/FDDP 的对照另设实验组。

### 对照对象与研究问题

| 控制器 | 待优化对象 | 用途 |
| --- | --- | --- |
| 手工规则 | 人工设定的速度/距离阈值、步长及周期选择规则 | 当前可解释工程基线 |
| CMA-ES 参数规则 | 与手工规则相同形式中的参数，包括上下行切换阈值及滞回宽度 | 衡量自动调参相对人工规则的收益 |
| CMA-ES 策略 | 与 PPO actor 相同结构、观测和动作解码的网络权重 | 比较优化算法 |
| PPO 策略 | actor 权重、探索参数和 critic | 当前学习基线 |
| 初始化策略 | 搜索或训练开始前的冻结 actor | 分离人工初始化与实际学习收益 |

参数规则与神经策略的比较同时包含表达能力差异，报告中需要注明。CMA-ES 策略与 PPO 使用同样的 actor 宽度、非线性、观测归一化规则和确定性动作映射。PPO 额外使用 critic，其计算与调参成本计入统计。

周期级任务统一开放 crawl/trot、相同步长范围和相同周期档位。参数规则通过阈值选择相同档位。CMA-ES 网络搜索使用连续权重，离散动作使用共享的解码规则；若参数搜索包含离散变量，预先固定其连续编码和取整方式。所有控制器使用相同的执行边界、请求等待、限幅及可行性干预规则。

逐足任务另建同权限对照组，保持导航参考、四足请求和请求处理一致。周期模板基线作为结构消融单独列出。

### 拟修改代码

- 集成仓库新增 `scripts/train_stage2_cmaes.py`，支持参数规则搜索和策略权重搜索，保存均值、协方差、步长、种群计数、随机状态及最佳候选。
- 在 `source/RL_Bezier_MPC/RL_Bezier_MPC/` 下新增共享实验模块，提取现有策略构造、动作解码、rollout、目标分配和指标计算。
- 新增 `scripts/evaluate_gait_controllers.py`，加载手工规则、CMA-ES 候选和 PPO checkpoint，使用同一测试配置输出逐回合及配对结果。
- 修改 `train_stage2_async8.py` 与 `stage2_training_state.py`，输出统一交互预算、时间、配置和模型选择记录。
- 阶段 4 复用同一评估与统计模块接入 `train_go2_augmpc.py`。固定 CMA-ES 依赖版本并在运行配置中记录。

### 环境与任务控制

- 固定两仓库版本、机器人模型、MPC 代价及约束、求解预算、warm start、传感器、控制频率、reset 和失败处理。
- 固定训练目标分布和初态分布，使用共同的场景种子表；候选评估在同一代采用共同场景，跨代按预定计划更换场景。
- 划分训练、验证和最终测试场景。验证集选择 checkpoint 和超参数，最终测试集只用于冻结方案的评估。
- 测试覆盖已见速度、未见中间速度、加减速、停止及切换阈值附近的往返变化，报告滞回和反复切换。
- 每个配对场景重置 MPC 缓存与机器人状态，场景顺序固定或配对随机化，记录实际执行顺序。

### 优化目标与预算

- CMA-ES fitness 与 PPO 使用同一任务奖励定义、权重和终止惩罚。按公共 rollout 约定累计奖励，明确折扣和周期持续时间的处理。
- 固定周期接口采用相同的持续时间计权；固定频率环境使用相同折扣。验证奖励计算器对同一轨迹给出一致回报。
- 正式运行前写入总交互预算 B、验证次数和调参预算。B 以所有环境实际执行的物理步总数为主，同时报告高层决策数、episode 数、模拟秒数和 MPC 调用次数。
- CMA-ES 种群中所有候选、重复评估和失败试验均计入 B；PPO 的全部采样也计入 B。早停失败仍保留失败惩罚与已消耗交互量。
- 在预先固定的预算比例检查点评估，例如 0%、25%、50%、75%、100%。记录批次粒度造成的预算偏差，最终候选遵守预设预算上限。
- 用相同硬件、并行环境数和资源上限测量墙钟耗时。分别统计采样、MPC、网络更新、搜索更新与评估耗时，额外绘制性能随墙钟时间的曲线。
- 各算法获得相同上限的超参数搜索交互预算，最终测试不参与调参。手工规则冻结参数并记录本次人工调参的评估次数；已有规则的历史开发成本标为未知。
- actor 初始权重在每个重复实验中配对。公共预训练或旧 checkpoint 的来源与成本必须记录，并同时向适用方法提供。

### 评估指标与统计

- 正式实验至少 3 个独立训练/搜索种子，每个冻结控制器至少 20 个测试回合，覆盖同一组配对场景。若统计不确定性过大，按预设扩样规则增加种子。
- PPO 关闭探索，CMA-ES 使用经验证集选定的固定候选，规则使用固定参数；全部重新执行物理评估。
- 主要指标在训练前固定，优先报告成功率和速度跟踪误差，同时报告到达时间、终点误差、能耗、支撑足漂移、跌倒率、MPC 回退率及切换连续性。
- 能耗计算统一使用实加关节力矩与速度，注明积分定义。CoT 仅在有效移动距离超过预定阈值时计算，静止和极短距离任务报告能量及平均功率。
- 失败回合保留在整体成功率和任务回报中；另报成功回合条件下的到达时间。时间耗尽作为删失/未到达记录，避免只比较成功样本。
- 报告跨训练种子的均值、离散程度和置信区间；用种子级汇总或分层统计处理同一策略的多个测试回合，避免把相关回合当作独立训练样本。
- 同时报告回报随交互预算的曲线、最终测试结果及墙钟成本；训练轮数和 CMA-ES 代数仅作运行标识。

### 验收与结论边界

- 相同动作和初态在公共执行器中得到一致的物理处理，身份、reset 和动作映射审计通过。
- 三类主要控制器及初始化对照的配置、预算、逐回合结果齐全，checkpoint/搜索状态可恢复，最终候选可重载复评。
- 明确回答自动调参相对手工规则的收益，以及相同 actor 表达能力下 CMA-ES 与 PPO 的差异。
- 分别报告最佳验证候选与最终测试表现，不预设任何算法获胜。结果接近或置信区间不足以区分时，保留这一结论。
- 算法对照本身以实验完整和可复现为完成条件；阶段 5 的任务收益目标仍按其预注册指标独立验收。
