故障期间主动回站立，对原任务约 22.3 mm 的偏离如实保留；“通过”表示旧包、回退、
恢复与当前安全参考的原门槛通过，不表示停包期间仍以 5 mm 精度跟踪原任务。

也不能把很小的误差差异解释为有统计意义的控制收益。

W/C0 的本轮五份轨迹分别与 `go2-z1-c0-paired-final` 中的相应轨迹一致；C1 首批和
复测也一致。每份核对 12 个数组，共 180 组，包括状态、实际力矩/力和请求快照。

## 实际耗时与规定交付时序

三组均使用 24×0.05 s 规划时域、2 Hz 名义请求、20 ms 名义 WBC、≤5 ms plant 子步。
原生求解真实运行，但交付统一采用可控时钟的 250 ms，前台阶段规定为 2/8 ms。
以下为首批同批完整原生请求阶段之和，包含预览、验收和导出，**不是**规定交付延迟。

| 任务 | 请求 p50 ms：W / C0 / C1 | 请求 p95 ms：W / C0 / C1 |
| --- | ---: | ---: |
| hold | 142.84 / 174.67 / 516.85 | 190.11 / 208.26 / 559.96 |
| reach | 152.89 / 177.06 / 530.01 | 170.13 / 256.06 / 659.61 |
| high_low | 164.63 / 227.36 / 588.05 | 185.48 / 248.42 / 611.27 |
| failure | 158.89 / 235.03 / 623.65 | 183.96 / 307.06 / 734.37 |
| expired | 153.18 / 230.61 / 569.54 | 175.27 / 304.62 / 657.89 |

C1 的各任务阶段中位数：未来 Ag 映射约 6.7–7.3 ms，逐节点静态 QP 182–209 ms，
质心求解/验收 202–294 ms，含物理重算的 Guidance 导出约 44–46 ms；完整分项见 JSON。
阶段中位数之和一般不等于总请求中位数。当前首版明显慢于 C0/W，实际请求常超过
250 ms 交付假设及 500 ms 规划周期，不视为真实后台 2 Hz 或硬实时通过。
复测耗时另存，操作系统调度与机器负载未受控；不通过挑选较快的一轮宣称性能收益。

没有加入动态闭环模型；这些数值不是实际 Z1 额定载荷。

6 kg 静态探针在固定四足和 TCP 位姿、基座 ±(8,6,7.5) cm/0.3 rad 及原关节界内

## 复现及原始文件

三组实验入口与环境命令见 [实现说明](../../go2_z1_c1.md)。本轮路径为：
`artifacts/go2-z1-c1-probe/`、`go2-z1-c1-paired-first/`、`go2-z1-c1-recheck/`、
`go2-z1-c1-tests/`、`go2-z1-c1-audit/`（均在 artifacts 下）。NPZ 全状态和逐步 WBC
QP 日志保留在这些忽略目录；归档 JSON 保留源码/轨迹哈希及全部规划候选/故障事件。

在已有环境变量下，独立复核反馈、轨迹和静态探针：

```bash
.venv/bin/python -B examples/go2_z1_c1_audit.py \
  --paired artifacts/go2-z1-c1-paired-first \
  --recheck artifacts/go2-z1-c1-recheck \
  --baseline artifacts/go2-z1-c0-paired-final \
  --output artifacts/go2-z1-c1-audit-rerun/execution_audit.json
```

输出必须新建；不覆盖首次异常或历史失败与复测。
